### Recent (2026-08-10, Monday late night — Inkpress v1.0.4: blank-article rendering fixed with WKWebView)

Debugged and fixed Inkpress's completely-blank article bodies that were blocking the app's usefulness. SwiftUI's Text() view cannot render NSAttributedStrings containing NSTextAttachments—which is exactly what NSAttributedString's HTML importer creates when parsing `<img>` tags (every journal post opens with a banner image). The feed/parse layer worked fine (verified live production feeds return 16KB+ HTML per entry), but the rendering silently produced nothing. Switched to rendering post HTML in a WKWebView with an inline stylesheet, which also gets images, code blocks, and link-open-in-Safari behavior automatically. Verified in iOS simulator that article text and banner images now render correctly. Bumped to v1.0.4 but holding from submission due to the Guideline 5.6 freeze until August 18.

### Recent (2026-08-10, Monday night late — HEALSTACK 2.1(a) ROOT CAUSE FOUND AND FIXED: Supabase demo account had NULL columns)

Healstack's Guideline 2.1(a) "Unable to log in" rejection is solved. The demo account Apple's reviewers use (healstack.demo@heyitsmejosh.com) had NULL values in the Supabase auth.users table columns email_change and email_change_token_new. GoTrue's Go runtime scans those fields into non-nullable Go strings, so any auth call touching that row threw a 500 error: "Database error querying schema" on login, "Database error finding user" on signup. A normal wrong-password login returns a clean 400, so the 500 was specific to that one corrupted row. Exactly 1 of 9 users was affected — the demo account. Fixed with: `update auth.users set email_change = coalesce(email_change,''), email_change_token_new = coalesce(email_change_token_new,'')` for that row. Verified after the fix: the same login now returns a clean 400 invalid_credentials instead of a 500. No app code change needed. Still to do: sign in once end-to-end with the real demo password (password hash is redacted in API views), then rebuild and resubmit after Aug 18. This is a valuable lesson: when App Review says "unable to log in", test the EXACT demo credentials from `asc review details-for-version`, and treat a 500 (not 400) on auth as a sign of corrupted user row data, not app code.
